# Lang App — multi-language spec (v2.0)

## 1. Master prompt (rewritten)

> **Lang App is a free, installable web app where a person picks the language they speak and the language they want to learn, then studies in 5-minute sessions: taught-then-quizzed cards with audio, spaced-repetition review, short lessons, drills, and a playful 3D layer.**
> Version 2.0 turns the single Korean-for-English-speakers app into a **course platform**:
> 1. After the intro and sign-in, a **language home** asks *"What language do you speak?"* (English or 한국어 available; other languages shown locked under "Coming soon"), then *"What do you want to learn?"* (the course available for that native language, plus locked "Coming soon" languages).
> 2. Two live courses: **`en-ko`** (English speakers learn Korean — the existing app, unchanged in content and progress) and **`ko-en`** (Korean speakers learn English — new content, and the whole interface in Korean).
> 3. Adding a language later must be a content job: drop a course pack (and a UI dictionary if it brings a new native language) into `packs/` — no engine rewrite.
> Everything already shipped must keep working: sign-in and sync, feedback board, privacy/delete-account, offline/PWA, strict CSP, 3D effects, review/practice/session flows, the test harness.

## 3. Data contracts

### 3.1 Course object
The engine exposes `COURSES` (map) and `COURSE` (active). The built-in course is assembled in `src/app.html` from the existing globals:

```js
COURSES['en-ko'] = { id:'en-ko', native:'en', target:'ko', ttsLang:'ko-KR', name:{en:'Korean',ko:'한국어'}, brand:'한글',
  DECKS, GROUPS, TAGS, DESC, DIALOG, EXAMPLES, LESSONS, CHECKS, PATTERNS, PAIRS, GOALS, PLAN_PRESETS, TITLES, PAUSE:{sets:PAUSE_SETS, idioms:IDIOMS}, features:{script:true, pron:true, conj:true, register:true, numbers:true, sound:true, strokes:true} };
```

Pack courses arrive as `LANGAPP_PACKS.course['ko-en']` with the **same keys**. Card tuple everywhere: `[target, pron, meaning, note]`
- `target` — text in the language being learned (spoken by TTS in `ttsLang`)
- `pron` — pronunciation aid in the learner's script (en-ko: romanization; ko-en: 한글 발음, e.g. `"익스큐즈 미"`)
- `meaning` — in the native language
- `note` — short usage note in the native language (may be `""`)

### 3.2 `packs/course-ko-en.js` (content agent)
```js
LANGAPP_PACKS.course['ko-en'] = {
  id:'ko-en', native:'ko', target:'en', ttsLang:'en-US', name:{en:'English', ko:'영어'}, brand:'English',
  features:{ script:false, pron:false, conj:false, register:false, numbers:false, sound:false, strokes:false },
  DECKS:{ "<덱 이름 (Korean)>": [ ["Excuse me.","익스큐즈 미","실례합니다 / 저기요","사람을 부르거나 지나갈 때"], … ] },

  TAGS:{ "<tag>": ["<덱>", …] },                       /* every deck in ≥1 tag; tag keys lowercase ascii or Korean */
  DESC:{ "<덱>": "<한 줄 설명>" },

  LESSONS:[ { id:"<ascii id>", title:"1 · …(Korean)", blurb:"…", deck:"<existing 덱>", body:"<html>" } ],
  CHECKS:{ "<lesson id>": [ ["<질문>", ["<opt>","<opt>","<opt>","<opt>"], <correctIndex>, "<해설>"], ×3 ] },
  PATTERNS:[ ["<pattern>", "<설명 (Korean)>", "<example (English)>", "<lesson id>"] ],

  TITLES:[[1,'Beginner','입문'],[3,'Student','학생'],[5,'Talker','수다쟁이'],[8,'Traveler','여행자'],[12,'Local','현지인'],[16,'Pro','고수'],[20,'Master','달인']],
  PAUSE:{ sets:{ compliment:["Compliment · 칭찬", [["You're amazing","정말 대단해요"], …]], expression:["Everyday · 일상 표현",[…]], polite:["Polite · 예의",[…]], saying:["Saying · 명언",[…]] },
          idioms:[ ["Break a leg","행운을 빌어!","브레이크 어 레그","공연·시험 전에 하는 응원"], … ] }   /* [idiom, 뜻, 발음, 설명] */

```
Lesson `body` is an HTML **string** using only: `<p> <h3> <ul> <li> <b> <i> <div class="tip"> <div class="tbl"><table><tr><th><td class="k">` and example rows written as tokens `{{ex:English text|한글 발음|한국어 뜻}}` (the engine expands them to audio rows). No scripts, no inline handlers, no backticks issues (it is a normal string — escape quotes).

Size targets (quality over raw count, natural modern English, 존댓말 explanations): **≥16 decks, ≥260 cards, ≥9 lessons each with 3 checks, ≥60 DIALOG, ≥40 EXAMPLES, ≥20 PATTERNS, PAUSE sets ≥18 items each, ≥24 idioms**. No duplicate `target` across the whole course (case-insensitive). No two cards in one deck with the same `meaning`. Every DIALOG/EXAMPLES key must be an existing card target. Every lesson `deck`, GROUPS/TAGS/GOALS deck name must exist.
Suggested decks: 인사, 자기소개, 생존 영어 1·2, 길 묻기·교통, 식당 주문, 카페·편의점, 쇼핑·계산, 숫자·시간·날짜, 스몰토크, 감정·반응, 직장·이메일, 전화·문자 줄임말, 칭찬·호감 표현, 여행(공항·호텔), 병원·긴급, 구동사(phrasal verbs), 발음 주의(R/L·F/P·TH·V/B minimal pairs), 영어 관용구.
Suggested lessons: 발음 함정(R/L, F/P, TH, V/B), a/the 관사, be동사와 일반동사, 공손하게 부탁하기(Could you…/Would you mind…), 시제 기초(현재·과거·미래), 전치사 in/on/at, 스몰토크 문화, 구동사 입문, 숫자·시간 말하기, 이메일 영어.

## 4. Engine work (`src/app.html`)

### 4.1 Language home
- Full-screen view (same visual family as the welcome screen; phone-first, both themes, safe-area aware), shown **after** the intro and the sign-in/nickname welcome, and **before** onboarding, whenever no course has been chosen. Steps:
  1. "What language do you speak? · 어떤 언어를 사용하세요?" — big tappable rows for English and 한국어; below, a "Coming soon · 출시 예정" list of locked languages (🔒, disabled, visibly dimmed, not focusable as actions; tapping does nothing but may show a "coming soon" toast).
  2. "What do you want to learn?" (in the chosen native language) — live course(s) for that native language as tappable rows, then locked "Coming soon" languages. Back button to step 1.
- Bilingual until native is known; afterwards everything is in the native language.
- Reachable later: a language/course switcher button in the header (shows target flag) and a row in Progress settings. Switching course never loses progress in the other course.
- The welcome (sign-in / nickname) screen appears before native is known → make its copy bilingual (English + 한국어).
- Existing users (have `ko-app2` data and no meta) are migrated silently to native `en`, course `en-ko` — they must **not** be forced through the language home, and their progress, streak and settings must be intact.

### 4.2 Per-course state and sync
- `la-meta` (localStorage): `{v:1, native, course, picked:1}` + device prefs that should be global.
- Course state: `en-ko` keeps using `ko-app2` (back-compat). Other courses use `la-s-<courseId>`. Global identity/prefs (nick, welcomed, fx3d, sfx, haptics, accent, zoom, quizRom, fbMine, fbLast) are shared across courses; learning data (cards, days, xp, lessons, checks, hist, rlog, custom, notes, onboard, plan…) is per course.
- Supabase `progress.state` (one row per user): keep the en-ko state at the top level exactly as today (old clients keep working) and add `_courses:{ '<id>': <state> }` and `_meta:{native,course}`. Merge each course with the existing `mergeState`; never drop a course the local device doesn't know. The claude.ai artifact sync path (`claude.use('db')`) gets the same shape.
- `sanitizeState` must run on every course state.

### 4.3 Course switching
- `applyCourse(id)` swaps all content globals (convert the `const` content tables to `let` or route through `COURSE`), rebuilds derived structures (`names`, `PATH`, My-phrases deck, memo caches, sentence pool, sound pool, idle slides…), loads that course's state, re-renders. No page reload required (a reload is acceptable only if state is fully saved first).
- Everything that hard-codes Korean must go through the course: TTS/speech-recognition language (`ttsLang`), `SAY` overrides (ko only), header brand, greetings, level titles, onboarding questions/goals/plan presets, intro particle word (en-ko "한글", ko-en "English"), pause-scene sets (`COURSE.PAUSE`), "Hangul"-specific copy.
- Feature flags gate Korean-only machinery: Hangul/alphabet decks and drills, syllable builder, numbers drill, register drill, sound-changes drill + pronunciation line on cards, stroke order, verb conjugator, auto-romanization of custom phrases, any `/[가-힣]/` assumption about `target`. Replace `/^Hangul|^Pronunciation/` deck-name tests with a course-aware helper.
- For `ko-en` the drills tab keeps the generic modes: Listen (hear → pick), Type (see meaning → type the English; case/punctuation-insensitive), Role-play (DIALOG), Say it (speech recognition in `ttsLang`). Tab label becomes generic ("Drills").
- "Romanization" toggles become "pronunciation hint" toggles (label via i18n).
- Review/session multiple choice, practice quizzes, learn-5 loop, lessons (+ `{{ex:…}}` token expansion), browse, search, custom phrases, exams, certificates must work for both courses.

### 4.4 Interface language
- `t(s)` → if native is `ko`: `exact[s]`, else first matching `patterns`, else `s`. Use `t()` for strings built in JS where practical.
- `translateDom(root)` + a debounced `MutationObserver` translate text nodes and `placeholder` / `aria-label` / `title` attributes when native ≠ en; remember the source string per node so switching back to English restores it. Skip subtrees marked `data-noi18n` — mark course content (card faces, options showing target/meaning, lesson bodies, dialogue/example text, feedback posts, user-typed text, nicknames).
- `<html lang>` follows the native language. Date/number formatting uses the native locale.
- New strings added by the engine agent (language home, switcher, drills labels, coming soon…) must be added in both languages by the engine agent (inline bilingual constants are fine).

### 4.5 Harness (`harness.js`)
Keep all existing guards green for `en-ko`. Add guards: language home appears for a brand-new user and not for a migrated one; locked languages are disabled; choosing 한국어 → 영어 lands in the ko-en course with Korean UI; a full Today session completes in ko-en; course switch round-trip preserves both courses' progress; pack integrity for every course (no dup targets, grouped/tagged decks, lesson decks exist, DIALOG/EXAMPLES keys exist, every lesson has ≥3 checks); zero horizontal overflow at 390px in both courses on every route; no untranslated-string regressions list (print count of visible Latin-only UI strings in Korean mode, excluding `data-noi18n`).
